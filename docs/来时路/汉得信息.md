- 如果两个计算任务到来如何保证顺序执行？
```txt
当前并行计算框架对同一个worker使用FIFO Scheduler，用Scheduler.tashQueue，保证同步计算任务按入队顺序启动，独立批次通过多worker并行执行，并根据批次偏移量来合并结果，不依赖返回顺序。也不会出现说第二次任务的某个worker线程计算结果被拼入第一个计算任务中某块的情况，因为这里在做网格计算时，会创建一套独立的局部缓冲区和回调闭包，且Actor在分配任务时都有一个对应的id能够找到相应的回调，而每个回调闭包又有所属调用的临时局部buffer即vertices和对应worker线程计算结果在buffer中的偏移量fromStorageId。

Dispatcher采用round-robin来分发任务做负载均衡，框架本身不保证跨worker的全局顺序，也不保证异步任务的完成顺序。

取消机制可以移除尚未执行的执行的排队任务，并删除主线程回调来丢弃过期结果，但不能强制中断已经开始的同步计算，对于存在依赖的任务，需要在业务层使用Promise串行；对于只保留最新结果的任务，可以使用Cancelable加版本号；如果要真正停止运行中的计算，则需要AbortSignal、分片计算和协作式取消。

当worker正在执行同步计算任务时，新任务还没有进入Scheduler.taskQueue，新任务先暂存在浏览器管理的Worker消息队列中。等待计算中的任务完成后，事件循环可以处理新消息时，Actor将新任务排入Scheduler.taskQueue，Scheduler再通过throttledInvoker每轮取出一个任务执行。
```
