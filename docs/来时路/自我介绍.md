# 自我介绍

我希望应聘贵公司的前端正式岗位，未来继续深入前端工程化和全栈与复杂应用开发。谢谢。

### 项目一介绍
我在香港北部都会区城市雨涝洪风险评估系统中担任前端核心开发。这个项目主要面向建设选址与雨洪风险评估，需要在桌面端 GIS 系统中支持多源空间资源管理、网格拓扑编辑、模拟方案配置以及仿真结果展示。

我负责的重点是前端资源树、地图视图渲染、页面状态恢复以及高密度计算任务的前端调度。项目中比较大的挑战是：资源类型多、地图交互复杂，同时部分数值计算和数据同步如果放在主线程，会影响页面流畅度。

针对这个问题，我设计了 ResourceTree 和 ResourceNode 的树状数据管理层，通过工厂注册表按资源类型分发菜单和编辑组件，保证数据到视图的渲染链路清晰可扩展。对于页面切换导致的状态丢失问题，我用序列化结合 IndexedDB 缓存页面状态。并且针对密集计算任务，我搭建了 Actor、Dispatcher 和 WorkerPool 调度架构，把计算迁移到 Web Worker 中执行，配合 Scheduler 控制并发和任务取消，避免主线程阻塞。

最终项目实现了资源管理、方案配置、仿真结果展示和分析等核心能力，也让我对复杂前端状态管理、GIS 可视化和浏览器性能优化有了比较完整的实践经验。

### 项目二介绍
S（背景）：这个项目是一个面向内容创作者的 AIGC 内容创作与审核平台，主要解决传统 AI 工具只负责生成内容，但缺少多轮创作、内容治理和发布闭环的问题。

T（任务）：我参与搭建了从 AI 创作、内容编辑到审核发布的完整链路，重点解决流式生成体验、登录安全和 AI 内容合规三个问题。

A（行动）：技术上，前端采用 Next.js、React 和 Zustand，后端采用 Express、PostgreSQL，并接入兼容 OpenAI 协议的模型服务。我使用 SSE 和 AbortController 实现可中断的流式生成；通过 Access Token、Refresh Token 轮换和并发刷新合并，实现登录状态的无感续期；同时设计不可变作品版本，将规则检测与大模型审核结合，并通过 Agent Run、Step 和 Event 记录执行过程。  

R（结果）：最终项目形成了“创作—编辑—审核—改写—确认—发布”的完整闭环，同时提升了生成体验、认证安全性，以及审核流程的可追踪性。

### 项目三介绍
S（背景）：这个项目叫港口水环境与生态动力学精细化模拟平台，主要面向科研人员。过去运行 FVCOM 等水环境模型时，需要手动管理本地文件并通过命令行执行，操作链路长，而且计算进度和结果不方便统一管理。  

T（任务）：我主要负责案例、模型文件和计算任务这条前后端链路，希望把区域选择、文件上传、任务执行、进度追踪和结果访问整合到 Web 平台中。 

A（行动）：前端使用 React、TypeScript 和 Zustand，按案例、文件、任务拆分状态；通过 SSE 和服务端事件总线实时同步长任务进度，并使用虚拟列表优化大量文件的渲染。后端使用 Fastify、Prisma 和 RustFS，通过 Node.js Stream 完成大文件流式传输，并对接独立计算服务。 
 
R（结果）：最终形成了一套完整的在线模型计算工作流，降低了科研人员管理文件和运行命令的操作成本，也让我积累了复杂状态管理、实时通信和 Node.js 中台开发经验。WebGL 流场渲染由其他成员负责，我主要负责其上下游的数据与任务链路。
