# Agent八股
## 基础概念
### 什么是Agent
#### Agent概念解释
Agent不是接一句话回一段话，而是能在多步任务中自己决定下一步做什么：先想清楚计划，再查资料、调工具，把中间结果记下来，最后汇总成答案。
```txt
Agent ≈ LLM + Planning（规划）+ Memory（记忆）+ Tools（工具）
```
- LLM：大脑，负责理解、推理、生成自然语言与结构化计划
- Planning：把模糊目标拆成可执行计划，并在执行中动态调整
- Memory：短期上下文 + 长期知识，避免「说完就忘」或重复劳动
- Tools：手脚，如搜索、数据库、代码执行、API调用等。

#### Agent与普通LLM单词调用的区别
- 普通调用：输入prompt -> 模型输出文本，没有外部环境闭环
- Agent：输出往往是「下一步动作」（例如：调用某工具、更新记忆、结束），环境返回Observation（观察结果），再进入下一轮推理，形成多轮控制循环。

#### Agent自主决策能力体现在哪
- 在动作空间中选下一步（选哪个工具、传什么参数、是否结束）
- 在信息不完整时决定先澄清还是先建设再验证。
- 在失败时决定重试、换策略或请求人工介入（视系统设计而定）

#### Agent核心循环（典型ReAct/Tool-use范式）
- 抽象为：Thought（推理）-> Action（动作）-> Observation（观察）-> ... -> Final Answer。
- 实现上通常由「编排层」（Orchestrator）驱动：解析模型输出、执行工具、把结果写回上下文，直到满足停止条件。

#### 一句话说明什么是AI Agent
AI Agent是以大模型为认知核心，结合规划planning、记忆memory与工具调用tools，能在多步交互中根据根据环境反馈持续决策并完成任务的系统；其本质是“感知-思考-行动”的闭环循环，而不仅是单次文本生成。

#### 为什么说Agent = LLM + Planning + Memory + Tools？缺一块会怎样？
- 缺Planning：容易变成只会接话的聊天，长任务易跑偏或一步登天完不成
- 缺Memory：长对话丢线索，多会话无法延续用户偏好与任务状态。
- 缺Tools：只能空谈，无法查实时信息、执行代码、改系统状态。
- LLM：中枢，但是缺少外围则不是完整的Agent系统。

#### Agent的自主是否不受控
自主是在约束空间内的决策，有策略和护栏：
- 工具白名单
- 参数校验
- 人在回路（Human-in-the-loop）
- 预算与步数上限
- 输出审核

#### Agent与AutoGPT的区别
AutoGPT是早期「目标导向+工具」的产品形态，主要依赖于LLM的自主决策能力，但在规划、记忆和工具调用方面相对简单。而现代Agent则更加复杂，具备更完善的规划、记忆和工具调用能力，能够更好地处理复杂的任务。

### Agent vs LLM Chain vs ChatBot
#### 概念解释
- Agent：像项目经理，步骤不是完全写死的，模型根据当前观察决定下一步，可分支、可重试、可换工具。
- LLM Chain：像流水线，开发者预先写好步骤顺序，A接B、B接C，路径相对固定
- ChatBot：像前台接待，以对话为主，核心是接话和回复，通常不强调多步任务闭环与工具编排。

| 维度 | ChatBot | LLM Chain | Agent |
|------|---------|-----------|-------|
| 控制流 | 多为线性对话 | 开发者定义的 DAG/序列 | 模型驱动的分支与循环 |
| 工具 | 可有可无 | 可嵌入固定节点 | 动态选择与多轮调用 |
| 状态 | 主要会话上下文 | 链各节点显式传递 | 记忆 + 环境观察 |
| 适用 | 问答、闲聊、简单引导 | ETL 式固定流程 | 开放问题、研究、自动化任务 |

- Chain：控制流在代码里
- Agent：控制流在模型决策 + 环境反馈里（仍可由代码设边界）

```txt
[用户]
  │
  ▼
┌──────────────────────────────────────┐
│ ChatBot：对话管理 +（可选）知识检索      │
│ 输出：自然语言回复                      │
└──────────────────────────────────────┘

[用户]
  │
  ▼
┌─── 步骤1 ───►┌─── 步骤2 ───►┌─── 步骤3 ───► 输出
│  LLM/解析    │  LLM/转换    │  工具/API    │
└─────────────┴─────────────┴──────────────┘
        LLM Chain（控制流在代码中编排）

[用户]
  │
  ▼
┌──────────────────────────────────────┐
│ Agent 编排器                          │
│  loop: LLM 规划 → 选工具 → 环境反馈     │
│        → 写入记忆 → 直到终止条件        │
└──────────────────────────────────────┘
  │                    ▲
  ▼                    │
[工具/API/数据库/浏览器/代码执行环境]
```

#### Agent与Prompt Chain的本质区别
- Prompt Chain的拓扑与顺序主要由工程侧固定
- Agent在运行时在动作空间中做选择，依赖Observation更新信念，适合输入与路径不确定的任务

二者可结合：链式稳定流程，Agent负责链内某段的灵活分支

#### ChatBot加上插件是不是就成为了Agent
不一定，如果插件调用由固定规则出发（关键词路由），那么更像是「带工具的Bot」，若由模型在多步推理中自主选择工具与参数，并形成闭环迭代，则更贴近Agent，关键在是否具备多步自主决策与反馈闭环。

#### RAG + Chat算不算Agent
单次检索再回答偏向「增强型Chat」，如果有多轮检索策略（查不到换查询、分解子问题、交叉验证）则具备Agent特征。

### Agent的核心组成
#### 概念解释
- 感知：把多模态输入（文本、文件、接口返回、页面结构等）转成模型可用的表示，并抽取任务相关状态
- 规划：把目标拆成子目标与步骤，可以是 一次性计划 或 每步重规划
- 记忆：
    - 短期：当前会话上下文、工具轨迹
    - 长期：用户画像、文档知识、向量图、图数据库等
- 工具：对外部世界可执行的操作抽象：需有清晰schema（名称、描述、参数JSON Schema）
- 执行：真正调用工具或触发环境变化，并处理超时、重试、幂等等工程问题
- 反思：对失败或质量不佳的结果进行自省：纠错、换策略、生成检查清单（常与「自我批评 / 验证器」配合）

#### 原理详解
- 感知：常与结构化抽取、OCR、HTML解析、日志解析结合；关键是减少噪声进入上下文
- 规划：CoT/ReAct、Planner-Executor双模块、树搜索（LATS）、任务图等
- 记忆：摘要压缩、引用溯源、记忆冲突解决、权限与隐私
- 工具：最小权限、参数校验、错误信息回灌模型
- 反思：自我批评、验证器、回溯搜索、失败案例库、人工介入
