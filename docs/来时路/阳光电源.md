```txt
最大的区别在于：React是“重新渲染组件”为中心，Vue是“响应式数据”为中心。
```

- Vue 3 和 React 都有 Hooks，它们有什么区别？
```txt
- 状态机制不同：React靠把update加入fiber的updateQueue来触发render；Vue3则是修改value通过响应式系统找到依赖该值的副作用并调度相关组件更新。
- 依赖管理不同，React需要手动声明deps数组；Vue3则是自动收集依赖。
- 条件语句支持不同：React靠链表结构顺序管理hooks所以不能放入条件语句中以防破坏顺序；Vue3的ref本质返回独立响应式对象，不依靠hooks顺序，但Vue的生命周期钩子和依赖当前组件实例的API仍应在setup()中同步注册，不能在异步回调中注册。
- 闭包语义不同：React每次渲染都会产生一个新的变量快照，定时器捕获的是创建回调时捕获的state，React想获得最新值需要用函数式更新或useRef；Vue3的ref是稳定对象，回调执行时读取的value通常得到最新值。
- 副作用API定位不同：React显式维护deps数组，依赖变化时在commit阶段完成后浏览器绘制前异步重新执行副作用；Vue3的依赖是执行期间自动收集的，也可以明确监听某个响应式对象。
- 逻辑复用相似但返回内容不同：React返回的是本次render的状态快照和用于更新的dispatch函数；Vue3返回的是持续存在的响应式引用。

React是“函数式渲染快照 + 调度更新”，Vue3是“细粒度响应式系统”。
```

    - 让你重新设计，你会如何优化这套并发刷新与请求重放机制？
```txt
虽然这里做了promise单飞，但如果refresh token接口刷新过慢，会导致其他接口返回401后一直处于await状态挂起，会导致401风暴，而且没有明确的超时和错误收口。

重新设计的话会建立统一的AuthRefreshCoordinator，包含“发送前拦截 + 单飞promise + 失败补偿重放”：
1. 发送前主动刷新：发送请求前判断过期时间是否在30s内，是则由第一个发现token临期的请求触发刷新，其他请求在发往后端前挂起。
2. 保留401补偿机制：将新token存入store，记录请求使用的token，后续请求如果发现token过期则直接返回401，而不是A请求已刷新成功这时B请求使用着旧token发出的请求才返回401。B请求会触发补偿机制，携带新token重新发起请求。
3. 有界重放：把请求定义为可重新创建的函数：
    - 最多重放一次
    - 刷新接口本身禁止触发刷新
    - 支持调用方AbortSignal取消
    - 流式上传等不可重放请求直接报错，要求用户重新操作

目前项目中这套的问题是，当新token刷新请求已发出，但是别的请求仍会带着旧token进行请求得到401后才会挂起，需要添加请求前主动拦截。
```

```txt
1. 按缩放级别分层：LOD（Level of Detail），MapBox可以读取当前地图的缩放级别，可以根据不同缩放级别设置多组不同精细度的图层数据，根据缩放界限来切换不同精细度的图层数据。
```
